How Enigma Vault NoPII and Nightfall Handle One Prompt

Enigma Vault NoPII sits in the request path and swaps values both ways, while Nightfall’s Developer API returns findings and a redacted copy that your code then decides what to do with.

  1. With Enigma Vault NoPII: Your app sends the prompt to the Enigma Vault NoPII base URL. Enigma Vault NoPII detects a name and an email, replaces each with a consistent token, sends the tokenized prompt to the provider, and restores the real values in the reply.
  2. With Nightfall’s API: Your app sends the text to the scan endpoint, up to 500 KB and 50,000 items per request. Nightfall returns findings and a redacted payload, such as “[CREDIT_CARD_NUMBER]”, and your app sends that to the model.
  3. When the reply comes back: Enigma Vault NoPII has already restored the values. With Nightfall, the placeholders stay in the reply unless you chose encryption, in which case your code decrypts with your own private key.
Enigma Vault NoPII

If tokenization ever fails, Enigma Vault NoPII blocks the request rather than sending unprotected data. That is the architecture, not a setting, and every decision lands in the audit log.

Enigma Vault NoPII vs Nightfall on Redaction, Coverage, and Accuracy

Redaction Options in Nightfall’s Developer API

Nightfall’s Developer API, formerly called Firewall for AI, is the part your code calls directly. Nightfall’s redaction docs describe four ways to change a finding: mask characters, substitute a phrase, substitute the detector’s name in brackets, or encrypt with your RSA public key. Nightfall does not store your keys, so decryption is your job.

The first three are one-way. The fourth is reversible, but it hands your team the key management and the restore logic that Enigma Vault NoPII handles inside the proxy.

Restoring Real Values for Your Users

A support reply, a drafted letter, or a CRM note is only useful if it contains the right customer’s name. Enigma Vault NoPII keeps the mapping in Enigma Vault and restores it in every response.

Enigma Vault NoPII

Real values are revealed only to the end user who created the token, within their own session, under a time-boxed reveal grant, or to a server key with an opt-in scope. Every reveal attempt is logged, refusals included.

Coverage Beyond Your Application

This is Nightfall’s home ground. Its browser plugins, endpoint agent, and SaaS connectors watch copy and paste, uploads, USB, printing, and cloud sync, and can block, redact, or coach in the moment. Each user license covers two endpoint devices.

Enigma Vault NoPII covers none of this. It only sees the requests your applications route through it, so if your main risk is employees, it is the wrong tool.

Claude, Coding Tools, and the MCP Gateway

Nightfall’s Claude Inference Hooks allow or deny a prompt before the model runs, on Claude Enterprise, and its docs say tool calls, tool responses, and model responses do not fire on that integration. Its IDE and CLI hooks for Cursor, Claude Code, and VS Code scan prompts and tool calls, with model responses monitored only. Its MCP gateway, announced in September 2026, blocks sensitive data returned by tool calls.

Enigma Vault NoPII takes a different path for agents you build: detection runs on tool-call arguments and tool results inside the same request, and the agent receives real values back.

Detection Accuracy and False Positives

Nightfall advertises 95% detection precision and attributes it to its proof-of-value results. We found no independent benchmark or recall figure. Its G2 reviewers praise the coverage, and several also mention false positives, alert fatigue, and learning regex to exclude certain identifiers.

Enigma Vault NoPII publishes the results of 109 automated tests on its engine and checks checksums where a format allows. It also makes no independent accuracy claim, so test both on your own data.

Deployment and Data Residency

Nightfall runs as SaaS, and its security page names US hosting. We found no on-premises option in its docs. Enigma Vault NoPII runs as NoPII Cloud, and its self-hosted edition runs the proxy and vault in your environment on an Enterprise license.

Moving From Nightfall’s Developer API to Enigma Vault NoPII

If you built your AI feature on Nightfall’s scan API and now need real values back in responses, the change is in where scanning happens.

  • Find Every Scan Call: List each place your code calls the scan endpoint before a model call, and any code that decrypts or fills placeholders.
  • Keep What Still Fits: If you also use Nightfall for employees or SaaS apps, that work is separate and does not need to move.
  • Route One Provider First: Point one model client at the Enigma Vault NoPII base URL and compare what reaches the provider in the audit log.
  • Remove the Scan Step: Once results match, drop the scan calls on that path.
