Where Enigma Vault NoPII and Portkey Differ in Practice

PII Detection and Entity Coverage

Portkey’s built-in PII guardrail covers seven types: phone number, email, location, IP address, SSN, names, and credit card. Its docs say these patterns are standardized and not customizable for the pre-built check, though you can add your own regex rules or call a partner such as Azure or AWS Bedrock Guardrails.

Enigma Vault NoPII turns on 11 entity types by default and lets you switch on more than 25 others per workspace, including regional identifiers. It checks checksums where the format allows, catches 14 families of credentials in the same pass, and lets you add 25 to 500 custom terms depending on plan.

Restoring Real Values in Responses

Portkey’s PII redaction docs say redaction is irreversible by design and the transformation is one-way. If your feature writes a reply to a customer, your own code has to put the values back, and Portkey documents no mapping to do it with.

Enigma Vault NoPII keeps a mapping in Enigma Vault and restores the real values in the response before your app sees it. Real values are revealed only to the end user who created the token, within their own session, under a time-boxed reveal grant, or to a server key with an opt-in scope, and every reveal attempt is logged.

Streaming Responses

Portkey’s guardrails docs say input guardrails run before the stream starts, while output guardrails run on the full response after the stream completes and take no action, so their results are informational only.

Enigma Vault NoPII

Enigma Vault NoPII replaces tokens as each chunk arrives, so latency impact stays small even on long completions. Tool-call arguments are buffered until the call completes and released as one piece, so a token split across chunks never breaks the JSON your agent is parsing.

Agents, Tool Calls, and MCP

Portkey offers an MCP gateway that centralizes authentication, access, and observability for MCP servers. That is valuable if you run many agents against many tools.

Enigma Vault NoPII is not an MCP gateway. It runs detection on message content, system prompts, tool-call arguments, and tool results, so an agent that reads a ticket and calls a CRM never sends the customer’s details to the model provider in either direction.

Routing, Caching, Fallbacks, and Observability

This is Portkey’s home ground. It offers a unified API, automatic fallbacks, load balancing, retries, simple and semantic caching, budgets, rate limits, and a dashboard that reviewers on G2 single out. Enigma Vault NoPII does none of this; it fronts 9 providers and keeps your privacy controls the same when you switch between them.

Enigma Vault NoPII does support tracing: Langfuse tracing on Growth and above records tokenized content only, and Enigma Vault NoPII honors the W3C traceparent header for OpenTelemetry.

Deployment and Self-Hosting

Portkey’s gateway is open source under the MIT license, and you can run it yourself for free. Its GitHub README lists PII redaction under the enterprise version, though, and Enterprise adds private cloud, VPC hosting, and data isolation.

Enigma Vault NoPII runs as NoPII Cloud on every plan. The self-hosted edition runs the proxy and vault inside your own environment under an annual Enterprise license with no token meter.

What Portkey’s Own PII Docs Say

Portkey does not publish a comparison page against Enigma Vault NoPII, so the fairest view of its PII features is its own documentation. Here is what it says, in plain terms.

  • Redaction Is One-Way: The docs say redaction is irreversible by design. That suits logging and classification, and it does not suit replies that must contain real values.
  • Pre-Built Patterns Are Fixed: The docs say redaction patterns are not customizable for the pre-built guardrail, though regex rules can be added.
  • Detect Is Not Redact: The Pro “Detect PII” check returns a yes or no verdict. Changing the request requires a redaction guardrail.
  • Plan Limits Apply: The guardrails docs give the free Developer plan basic, deterministic checks only, with partner and Pro guardrails on Production and Enterprise.
  • Streaming Output Is Monitored, Not Changed: Output guardrail results on streamed responses are informational.

Portkey’s guardrail counts also vary across its pages, from 20+ deterministic checks in the docs to 60+ guardrails on its features page, so ask which ones apply to PII on your plan.
